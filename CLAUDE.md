# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Terraform configuration for a personal Cloudflare Zero Trust account (`germanium.cz`): Access applications/policies, the Google identity provider, Gateway settings, WARP device profiles, and a cloudflared tunnel. There is no application code here — every `.tf` file is a thin, hand-maintained declaration of Cloudflare resources managed by the `cloudflare/cloudflare` provider (`~> 5.21`).

State is stored remotely in Terraform Cloud (org `mygermanium`, workspace `cloudflare-zero-trust`, see `versions.tf`) — do not assume a local state file reflects reality; `terraform.tfstate` in the working directory is not authoritative.

## Commands

```sh
source .env.cloudflare   # required before any terraform command; see below
terraform init
terraform plan
terraform apply
```

There is no build, lint, or test suite — this is declarative infra config, validated via `terraform validate`/`terraform plan` and applied directly.

## Secrets

Credentials live in `.env.cloudflare` (gitignored, not present on a fresh checkout) and must be sourced into the shell — Terraform does not read `.env` files itself, only real environment variables:

```sh
export CLOUDFLARE_API_TOKEN="..."
export CLOUDFLARE_ACCOUNT_ID="..."
export TF_VAR_google_idp_client_secret="..."   # Cloudflare never returns this once set
```

See README.md for where to obtain each value. `cloudflare_account_id` is also a non-secret Terraform variable set in `terraform.tfvars` (gitignored; template in `terraform.tfvars.example`).

## Structure and conventions

- Each `.tf` file groups one Cloudflare Zero Trust concern: `access_applications.tf`, `access_identity_providers.tf`, `access_policies.tf`, `devices.tf`, `gateway.tf`, `tunnels.tf`.
- **Access policies are defined once in `access_policies.tf` and referenced by id** from `access_applications.tf`'s `policies` block (with a `precedence` per app) — don't inline duplicate policies inside an application resource.
- `devices.tf` has a shared `local.warp_default_excludes` list (standard RFC1918/link-local/broadcast ranges) reused by both the default WARP device profile and any custom profile — extend that local rather than repeating the exclude list.
- Comments in the `.tf` files record *why*, not what (e.g. resources autogenerated by Cloudflare/WARP onboarding, or a note that a per-user device profile might be foldable into the default one) — preserve that context when touching those resources, and prefer adding a comment over silently reworking auto-generated-looking blocks.
- `provider.tf` reads the API token implicitly from `CLOUDFLARE_API_TOKEN`; there's no explicit `api_token` argument to edit.
